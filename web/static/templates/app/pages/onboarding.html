How a scrape works

Five stages, start to finish. Nothing leaves this machine at any point.

  1. Create the search. Name it, say where to look, and choose how thoroughly to cover the area. Open the wizard.
  2. Run it here. The job joins a local queue and starts when a worker is free. You can close the browser; the run keeps going.
  3. Watch and steer. Live progress per stage, with pause, stop, and download-partial-CSV available at any moment. Inspect jobs.
  4. Work the results. Filter, de-duplicate, and open any business for its contacts, website audit, and provenance. Open Results.
  5. Export what you keep. Send a filtered selection to CSV or XLSX, written into your local data folder. Open Exports.

Fast mode or Thorough mode

Fast mode is quick and uses no map grid: one pass per query inside a radius, fewer fields, and far less time. Thorough mode walks a grid of areas across the whole region for full map coverage, which is slower but finds places a single pass misses. Start with Fast mode.

“Stopped early” is not data loss

A run can stop early because it hit the Stop after limit, because you paused it, because the app shut down, or because some searches did not finish. Every committed row is already on disk: the CSV and the database rows stay downloadable, and a retry merges into the same output rather than replacing it.

What a good first run looks like

Collect broadly first. Enrichment is cheap to add later and expensive to wait for now.

  1. Keep the example search and leave it in Fast mode for the first pass.
  2. Leave website crawling and email extraction off until you have seen the raw list.
  3. Set Stop after to 60–90 minutes so the first run cannot surprise you.
  4. Watch the live monitor and download the partial CSV whenever you want a look.
  5. Filter and export the normalized records from Results.
