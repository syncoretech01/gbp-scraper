    Data fields retained

    The scraper stores every field returned by its selected mode so the original CSV stays compatible and future filters do not discard source data.

    Business

    Name, categories, status, description, rating, reviews, hours, price and identifiers when Maps exposes them.

    Location and contacts

    Address components, coordinates, phone, website, domain and emails when website crawling is enabled.

    Audit trail

    Source query, source URL, input identifier, extraction time, raw record, normalized value and field provenance.

    Fast Mode returns fewer fields.

    Use the normal browser/grid mode when complete listing details matter more than speed.

    Optional local enrichment

    Email extraction visits business websites and can substantially increase runtime. For the broadest first pass, leave it off and run a targeted second job later.

    Keep source data, filter safely

    All collected rows are preserved. After records commit, use Results to search and filter by rating, review count, category, city, status, website, email, phone, job and quality fields. This avoids losing data because of an overly strict scrape-time filter.

    Why there is no destructive pre-filter here

    Google can omit or change fields between list and detail views. Applying filters to the normalized local database is repeatable and auditable.

    Performance and browser capacity

    These values are saved with this job and applied by the local worker. Balanced is the safest starting point.

    Preset

    If reached, the job becomes Partial and keeps committed rows.

    Credentials are decrypted only in worker memory.
