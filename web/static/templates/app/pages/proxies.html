Import a proxy pool

HTTP, HTTPS, and SOCKS5 URLs are accepted. Credentials are AES-GCM encrypted with a random key stored beside the database and are never shown again.

Sticky strategies pin each query or map area to one proxy, which also enables per-proxy task caps and automatic pool-exhaustion pauses. Least recently used prefers the proxy idle longest, and an untouched proxy first.
0 means unlimited.
Paths, query strings, fragments, and unsupported schemes are rejected. Exact duplicates in the pool are skipped.
How proxy health is measured

On-demand tests record Maps access, response latency, exit IP, country, success/failure/block counts, cooldown, and automatic disable after repeated offline or authentication failures. Statuses are healthy, slow, rate-limited, blocked, authentication-failed, offline, and cooling-down. Use Retest disabled on a pool to test up to 50 disabled proxies and re-enable the ones that are healthy again.

Exit IP and country are measured from the test request itself, never from a third-party geolocation service: SOCKS5 reports the address it bound for the outbound connection, other protocols expose only the endpoint this host dialled, and the country is whichever Google region served the request. Each row states which of the two an address came from, and retesting stays operator-triggered rather than automatic.
